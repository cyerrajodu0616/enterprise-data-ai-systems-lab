Mental-model change

The starting model was one database engine selecting access paths and using CPU, buffer/cache memory, disk, temporary space, and parallel processes. Spark distributes physical work and schedules it in units:

Data → Partitions → Tasks → Stages → Executors / execution slots

Lazy transformations describe work. An action requires a result and triggers execution. When runnable tasks exceed available slots, tasks may run in scheduling waves. Exact parallelism was not observed.

Narrow versus wide work

Narrow dependencyWide dependency
Each output partition can be computed from a limited input partition dependency. Scan, filter, and projection can remain partition-local without required record redistribution.Records must be reorganized across partitions. Grouping equal keys commonly introduces Exchange and shuffle.

records across input partitions → grouping requirement → hash partition by key → Exchange → network shuffle → new shuffle partitions

Refinement: “One-to-one” describes useful dependency intuition, not unchanged row counts or a guaranteed physical plan. Confirm operators with explain().

Skew and the straggler

hot key (c-hot) → oversized shuffle partition → one expensive task → straggler → stage waits for slow task

Adding another executor does not necessarily split work already concentrated in one partition. Evidence would include generated key distribution, per-task or partition sizes, task durations, spill, and uneven completion. None was measured.

Recovery and retry safety

recoverable intermediate loss → lineage → rerun required parent work → recreate missing output

Spark can use lineage to recompute recoverable output when dependencies and sources remain available. This is conditional, not a claim that every failure avoids broader restart.

retryable distributed computation × non-idempotent external side effect = duplicate business-action risk

Deterministic computation is safer to recompute. External effects require idempotency or deduplication. LAB-005 will use only a safe synthetic sink—never a real payment or consequential system.
